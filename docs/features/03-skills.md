# 技能（Skills）

## 啥是技能

技能就是一段能复用的"任务流程说明书"。

举个例子，每次代码 review 你都要检查同样几件事：命名规范、安全漏洞、性能问题、测试覆盖。每次都重复说一遍很烦。

把这套流程写成技能，下次直接喊"帮我 review 代码"，WorkBuddy 就按你定的流程一步步来，不用再啰嗦。

## 技能和 AGENTS.md 啥区别

这俩容易混。说人话：

- **AGENTS.md** = 规矩。比如"代码风格用 4 空格缩进""提交前跑测试"。是一些全局规则，时刻生效。
- **技能** = 流程。比如"完整做一次代码 review"包含多步骤：读代码、查问题、写报告。是按需触发的任务流程。

规矩是"平时要遵守的"，流程是"要干活时按这个走"。

## 怎么创建技能

技能本质是个 SKILL.md 文件，放在指定目录下。

基本结构：

1. 在技能目录下建一个文件夹，名字就是技能名
2. 里面放一个 `SKILL.md`，写清楚这个技能干啥、怎么触发、走哪些步骤
3. 可选：放一些模板文件、参考脚本

SKILL.md 里要写明白：
- 这个技能解决啥问题
- 什么时候触发（关键词、场景）
- 执行步骤是啥
- 输出长啥样

::: tip 简单点
别一上来就写特别复杂的技能。先从 3-5 步的小流程开始，用顺了再加复杂逻辑。
:::

## 怎么用技能

用技能不用记命令，正常说话就行。

比如你写了个"周报生成技能"，触发词设了"写周报"。你直接说"帮我写周报"，WorkBuddy 识别到关键词，自动加载这个技能，按流程走。

也支持 `/技能名` 这种显式调用。

## 几个常见技能例子

**代码 Review 技能**

流程大概是：
1. 读取变更的代码
2. 检查命名规范
3. 找安全风险
4. 查性能问题
5. 输出 review 报告

**报告生成技能**

流程：
1. 收集数据来源
2. 按模板组织内容
3. 生成图表
4. 输出成 Word/PPT

**日报技能**

流程：
1. 读今天的任务记录
2. 总结完成情况
3. 列明日计划
4. 发到指定渠道

## 用技能的好处

1. **省事** - 不用每次都把流程说一遍
2. **一致** - 每次输出格式、步骤都一样
3. **可分享** - 写好的技能能给团队复用
4. **可迭代** - 流程变了改 SKILL.md 就行，不用重新教 AI

## 我的建议

::: tip 先用现成的
别一上来就自己写。先用 WorkBuddy 自带的技能，熟悉了再定制自己的。
:::

写技能最容易踩的坑：写得太笼统。比如"帮我做好代码 review"这种描述等于没写。要具体到步骤、具体到检查项。

另一个坑：一个技能塞太多功能。建议一个技能就干一件事，复杂任务拆成多个技能串起来用。
